Every input and output in the Claim Split HCFA macro

CLAIM.SPLIT.MACRO.HCFA pulls a repriced claim's data out of its PDF (or the WebClaims API), lays it across the MAIN grid, then keys it back into the mainframe as new split drafts — via one of three routines (Scratch, Scratch Not Online, Non‑Scratch) picked by a single dropdown. Almost every column downstream of "02.GET EDI DETAILS" is auto‑extracted output that later gets re‑read as split input; this page traces each cell through that round trip.

Reading the tables: row column N · New Cert # is input, only when Z2 Claim Split Option = SCRATCH or SCRATCH NOT ONLINE — same pattern as the release/pend macro reference: a cell only matters once its gating toggle says so.

ClaimInfo sheet — HCFA‑1500 box‑by‑box extraction

One row per claim. Every column here is output from CLAIM_DEMOGRAPHICS_INFORMATION, CLAIM_REPRICING_INFORMATION and Medicare_Medicaid_Cob_Information — nothing in this sheet is hand‑entered.

ClaimServiceLInes sheet — per‑line extraction

One row per service line per claim. All output, from CLAIM_SERVICELINES_INFORMATION, CLAIM_REPRICING_INFORMATION and Medicare_Cob_Information — this is the sheet POPULATE_MAIN_SHEET copies onto MAIN columns S–AI.

ColumnField

REFERENCE sheet — HCA → CPS POS lookup

A static two‑column table (col A "HCA POS", col B "CPS POS") maintained by hand, not per‑run.

Loaded into the HCFACol dictionary by HCFA_POS_Collection, and consulted only by HCFA_Scratch_NotOnline — it translates a service line's extracted place‑of‑service (detail‑grid column AH) into the CPS mainframe POS code before that value is keyed onto the new draft. The other two split modes (Scratch, Non‑Scratch) don't use this table — they carry the POS forward from the original claim's existing 450 screen instead.

Fixed values written to every generated draft

Hard‑coded constants in oShared — not read from any sheet, but written onto the CPS506 release screen (and the inel fields) for every draft any of the three split routines create.
